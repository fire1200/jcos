# 24시간 라이브 운영 런북 (처방 3-6)

**왜 필요한가.** 라이브는 단일 업로드보다 평균 시청 지속 시간이 3~6배 길다. 알고리즘에는 "지금 방송 중"이라는 별도 신호가 되고, 검색 결과의 실시간 슬롯과 홈 피드 라이브 섹션에 따로 노출된다. 업로드 사이의 시청시간 공백을 메우는 가장 값싼 방법이다.

## 1. 구성

| 항목 | 설정 |
|---|---|
| 제목 | `24시간 아기 수면음악 라이브 \| 신생아 자장가 백색소음 24시간 연속` |
| 썸네일 | 밤잠 시리즈 레이아웃 + 빨간 LIVE 배지 |
| 시청자층 | 아동용 아님 (롱폼과 동일 기준) |
| 카테고리 | 음악 |
| 지연 시간 | 일반 지연 (낮은 지연 불필요, 안정성 우선) |
| 채팅 | 켜기. 느린 모드 30초, 금지어 필터 |
| 콘텐츠 | 대표 롱폼 4~6개를 순환 재생 |
| DVR | 켜기 (시청자가 앞 구간으로 이동 가능) |

## 2. 송출

24시간 무인 송출이므로 자동 재시작이 핵심이다.

### ffmpeg 순환 재생 예시

재생목록 파일 `playlist.txt`:
```
ffconcat version 1.0
file night_01.mp4
file night_02.mp4
file whitenoise_01.mp4
file night_03.mp4
file playlist.txt
```
마지막 줄이 자기 자신을 다시 부르며 무한 순환한다.

송출 명령:
```bash
ffmpeg -re -f concat -safe 0 -stream_loop -1 -i playlist.txt \
  -c:v libx264 -preset veryfast -b:v 3000k -maxrate 3000k -bufsize 6000k \
  -g 60 -keyint_min 60 -pix_fmt yuv420p \
  -c:a aac -b:a 160k -ar 44100 \
  -f flv "rtmp://a.rtmp.youtube.com/live2/<스트림키>"
```

- `-g 60`: 키프레임 2초 간격. 유튜브 권장값이다.
- 정적 화면이므로 3Mbps로 충분하다.

### 자동 재시작 (systemd)

```ini
[Unit]
Description=YouTube 24/7 sleep music stream
After=network-online.target

[Service]
ExecStart=/usr/local/bin/stream.sh
Restart=always
RestartSec=10
User=stream

[Install]
WantedBy=multi-user.target
```

`stream.sh`에 위 ffmpeg 명령을 넣는다. `Restart=always`가 끊김 시 10초 후 재연결한다.

## 3. 일상 점검

| 주기 | 항목 |
|---|---|
| 매일 | 라이브가 살아 있는지, 동시 시청자 수, 채팅에 스팸이 없는지 |
| 주 1회 | 순환 목록에 최신 롱폼 추가, 오래된 것 교체 |
| 주 1회 | 설명란의 신작·재생목록 링크 갱신 |
| 월 1회 | 스트림 키 노출 여부 점검, 인코더 로그 확인 |

## 4. 라이브 → 채널 전환 장치

라이브 시청자를 정규 영상과 구독으로 넘기는 것이 목적이다.

- 설명 상단 3줄: 신작 링크, 재생목록 링크, 구독 안내.
- 고정 채팅 메시지: `밤새 끊김 없이 이어집니다 🌙 오늘 올라온 새 자장가는 설명란 첫 줄에 있어요`
- 라이브 화면 하단에 작은 채널명 워터마크. 화면 전체를 가리지 않는 크기.

## 5. 장애 대응

| 증상 | 원인 | 조치 |
|---|---|---|
| 스트림이 "오프라인"으로 표시 | 인코더 연결 끊김 | systemd가 자동 재시작. 3회 이상 반복되면 네트워크·비트레이트 점검 |
| 화질 저하 경고 | 업로드 대역 부족 | 비트레이트를 2000k로 낮춘다 |
| 저작권 클레임 | 순환 목록에 라이선스 문제 음원 | 해당 영상을 목록에서 즉시 제거, 스트림 재시작 |
| 동시 시청자 0 유지 | 검색 노출 안 됨 | 제목 키워드 점검, 썸네일 교체, 스트림을 한 번 종료 후 새로 시작 |
